Concept of the day

Quorum-based replication

5 min
Distributed systems

Balancing consistency and availability

A quorum is the minimum number of replicas that must acknowledge an operation. With N replicas, read quorum R and write quorum W, R + W > N ensures read and write quorums overlap.

N = 3 replicas\nW = 2 acknowledgements\nR = 2 replicas\nR + W = 4 > 3 → quorum intersection

Important: quorum intersection alone does not guarantee linearizability. Concurrent writes, versions, reconciliation and failure handling still matter.

Think it through

During a network partition, which side can accept writes if W = 2? What changes if the system prioritizes availability over strong consistency?

C++ / DSA challenge

Implement an LRU Cache

Medium · 20–30 min
Data structures · O(1) average

Design an LRU cache with get(key) and put(key, value). When capacity is exceeded, evict the least recently used key.

LRUCache cache(2);\ncache.put(1, 10);\ncache.put(2, 20);\ncache.get(1); // 10\ncache.put(3, 30); // evicts key 2\ncache.get(2); // -1

Hint

Combine std::list for recency order with std::unordered_map for lookup. Move recently used entries to the front; evict from the back.

What to test
  • Get a missing key.
  • Update an existing key.
  • Access a key before inserting at capacity.
  • Capacity of one.
